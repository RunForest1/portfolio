# portfolio

*[Read in English](./README.md)*

Это моё личное портфолио: место, где я показываю свои проекты. У каждого — отдельный
кейс, в котором разбираю задачу, решение и то, что сделал бы иначе. Сайт состоит из
одностраничника с прокруткой и отдельной страницы на каждый проект.

Сам сайт — тоже демонстрация моей работы во фронтенде, поэтому требования к нему у
меня такие же, как к любому проекту для заказчика: контент важнее эффектов, эффекты
не мешают, а 3D-фон чисто декоративный, грузится лениво и полностью отключается.

Онлайн: <https://runforest1.github.io/portfolio/>

## Зачем я это делаю

Сайт рассчитан на технических рекрутёров, тимлидов и потенциальных заказчиков —
люди в основном открывают его с телефона и тратят около 40 секунд. За это время
первый экран должен показать, как я работаю с фронтендом, следующие 30 секунд —
ответить на вопрос «что человек сделал, на чём и где код», а в конце должен быть
простой способ со мной связаться.

Отсюда два жёстких правила:

1. **Сайт — это витрина навыка.** Небрежная анимация, дёрганый скролл или четыре
   секунды до первого кадра вредят сильнее, чем отсутствие 3D вообще.
2. **Контент важнее эффекта.** Фон не должен мешать читать, кликать и работать с
   клавиатуры.

## Что есть на сайте

- **Hero** — моё имя, одна строка о специализации и кнопки действий.
- **Work** — грид проектов, который я курирую вручную в `src/data/projects.ts`, а не
  автоматическая выгрузка из GitHub: автоподтяжка вытаскивает форки, учебные задания
  и недоделки и отнимает контроль над обложкой и описанием — то есть ровно над тем,
  что продаёт проект. Живые данные GitHub (последний пуш, звёзды, основной язык)
  подмешиваются поверх по полю `links.repo`, но состав списка не определяют. Есть
  фильтр по технологии; его состояние хранится в URL (`?tech=react`), чтобы
  отфильтрованным видом можно было поделиться.
- **Страницы кейсов** (`/work/:slug`) — для проектов, которые стоит разобрать
  подробнее: problem / solution / outcome / lessons, галерея и навигация
  «предыдущий / следующий проект».
- **Stack** — технологии, с которыми я работаю, по категориям, без выдуманных
  процентов владения.
- **Contact** — email с копированием в один клик, ссылки на GitHub/Telegram и
  плашка доступности для работы.
- **Навигация** — якорные ссылки и ссылка на GitHub в виде виджета у правого края
  экрана; на мобильном сворачивается в кнопку меню (`src/app/Header.tsx`).
- **Язык и тема** — весь интерфейс и весь контент проектов на русском и английском
  (переключатель в шапке); по умолчанию тёмная тема, есть светлая (переключатель в
  виджете шапки). Оба выбора сохраняются в `localStorage`.

## Запуск локально

Нужны Node.js ≥ 22.6 и [pnpm](https://pnpm.io).

```bash
pnpm install
pnpm dev            # дев-сервер
pnpm build          # прод-сборка, base "/" (падает на ошибках типов)
pnpm build:pages    # прод-сборка, base "/portfolio/" — для GitHub Pages
pnpm preview        # локальный просмотр сборки с base "/"
pnpm preview:pages  # локальный просмотр сборки для GitHub Pages, на /portfolio/
pnpm typecheck      # tsc --noEmit
pnpm lint           # eslint --max-warnings=0
pnpm test           # vitest run
```

Прежде чем считать изменение готовым, я прогоняю
`pnpm typecheck && pnpm lint && pnpm build`.

## Структура проекта

```
src/
  app/                    # роутер, лэйаут, шапка/футер, UI-стор, глобальные стили
  pages/                  # Home, ProjectPage (/work/:slug), NotFound
  sections/               # по папке на секцию главной (Hero, Work, Stack, Contact)
  components/             # общий UI: Button, Tag, Section, Logo, ...
  scene/                  # ВСЁ, что импортирует three.js — изолировано намеренно
    Backdrop.tsx          # точка входа, грузится через lazy(), чтобы three не попал в основной чанк
    layers/               # слои параллакса из решётки точек
    hooks/                # параллакс от курсора, reduced-motion, определение вьюпорта
    config.ts             # все магические числа сцены в одном месте
  data/
    projects.ts           # курируемый список проектов
    stack.ts              # справочник технологий для карточек и фильтра
    site.ts, contact.ts   # метаданные сайта и контакты
  lib/                    # утилиты без React (i18n, storage, github, ...)
  types/
public/                   # обложки, галереи, og-image, favicon, 404.html
scripts/                  # генератор sitemap.xml / robots.txt
```

`three` импортируется только внутри `src/scene/`; остальное приложение знает о нём
через один лениво загружаемый компонент `<Backdrop />`. Если three.js когда-нибудь
попадёт в основной чанк, я считаю это багом.

## Дизайн

Я выбрал направление **«инженерная телеметрия»**, а не неоновый киберпанк:
холодный металл, точные тонкие линии, один сигнальный цвет (`--color-signal`) только
для интерактивного, много воздуха. Никаких глитч-эффектов, сканлайнов и
фиолетово-голубых градиентных заливок. Цвета — токены из `global.css`; хардкод hex в
JSX запрещён.

3D-фон — три слоя точек на разной глубине, образующие разреженную решётку. Она
сдвигается параллаксом от курсора и скролла и медленно «дышит». Фон рассчитан на
периферийное зрение и не должен отвлекать: `aria-hidden`, `pointer-events: none`,
не участвует в порядке фокуса.

## Бюджеты производительности и доступности

| Метрика | Порог |
|---|---|
| LCP (мобильный, 4G) | < 2.5 s |
| Initial JS (gzip, без чанка 3D-сцены) | < 120 kB |
| Чанк сцены (gzip) | < 250 kB |
| CLS | < 0.05 |
| Lighthouse Performance (мобильный) | ≥ 90 |
| Lighthouse Accessibility | 100 |

Доступность я проверяю в каждой итерации, а не откладываю на финальный проход:
настоящие рамки фокуса, семантические landmark-ы, полное управление с клавиатуры и
ручной **lite-режим** (переключатель в футере, сохраняется в `localStorage`),
который полностью размонтирует 3D-сцену и освобождает геометрии и материалы. При
`prefers-reduced-motion: reduce` рендерится один статичный кадр вместо анимации.
Если эффект не влезает в бюджет, я упрощаю эффект, а не поднимаю порог.

## Как добавить проект

Проекты курируются вручную в `src/data/projects.ts`. Каждая видимая строка —
`LocalizedText` (`{ ru, en }`), а стек проекта — список `TechId` из
`src/data/stack.ts`, а не свободный текст.

### Галерея

1. Положите скриншоты в `public/gallery/<slug>/` — по папке на проект, с именем,
   равным `slug` проекта.
2. Опишите каждое изображение хелпером `galleryImage()` из `src/lib/gallery.ts`:

   ```ts
   gallery: [
     galleryImage('my-project', 'shop.png', 1600, 1000, { ru: 'Страница магазина', en: 'Shop page' }),
   ]
   ```

   Ширина и высота — реальные размеры файла в пикселях: они нужны, чтобы
   зарезервировать место и не получить сдвиг раскладки (CLS), а автоматически при
   сборке они не определяются. Единственная обложка проекта (для карточки в гриде и
   Open Graph) остаётся плоским файлом `public/covers/<slug>.svg|png|webp`.

## Локализация

Весь текст, который видит посетитель, с самого начала есть и на русском, и на
английском — «переведу потом» не бывает. Статичные строки интерфейса (подписи
навигации, заголовки секций, тексты кнопок, aria-label) лежат в одном словаре
`src/lib/i18n.ts` и читаются через `useT()`. Всё, что относится к конкретному
проекту (заголовок, тэглайн, highlights, текст кейса, alt картинок), хранится как
`LocalizedText` прямо в `src/data/projects.ts` и достаётся через
`pick(locale, text)`. Выбранный язык сохраняется в `localStorage` и управляет
`<html lang>` и форматированием дат (`src/lib/date.ts`).

## Деплой

Сайт деплоится на **GitHub Pages** как project-сайт через
`.github/workflows/deploy-pages.yml`: каждый push в `main` запускает typecheck,
lint, тесты, `pnpm build:pages` и публикует `dist/`. Единственный ручной шаг —
один раз включить это в репозитории: **Settings → Pages → Source → GitHub
Actions**.

Поскольку сайт живёт под подпутём `/portfolio/`, а не в корне домена:

- `vite.config.ts` ставит `base` в `/portfolio/` только при `GITHUB_PAGES=true`
  (выставляется воркфлоу); локально остаётся `/`.
- `basename` роутера повторяет `import.meta.env.BASE_URL` (`src/app/routes.tsx`),
  поэтому ссылки корректно резолвятся под подпутём.
- Любой путь к изображению, заданный в коде обычной строкой (не через `import`),
  проходит через `withBase()` (`src/lib/assetUrl.ts`) — Vite сам переписывает пути
  только внутри `index.html`, но не строковые литералы в `.tsx`.
- `public/404.html` возвращает неизвестные пути на `index.html` (у GitHub Pages нет
  серверного SPA-фолбэка) приёмом
  [rafgraph/spa-github-pages](https://github.com/rafgraph/spa-github-pages);
  `index.html` раскодирует путь обратно до того, как его прочитает React Router.

`pnpm build` (и `build:pages`) перед компиляцией также пересоздают `sitemap.xml` и
`robots.txt` из курируемого списка проектов (`scripts/generate-seo-files.mjs`),
поэтому каждая страница кейса с блоком `case` попадает туда автоматически. Если
позже сайт переедет на собственный домен — поменяйте `SITE_URL` в
`src/data/site.ts`, верните `base` в `vite.config.ts` на `/` и поправьте
продублированные теги в `index.html`.
