# CLAUDE.md

Инструкции для работы над проектом. Читать целиком перед первым изменением кода.

---

## 1. Что это за проект

Персональное портфолио разработчика. Одностраничник с прокруткой + отдельные страницы кейсов.

Аудитория: технические рекрутёры, тимлиды, потенциальные заказчики. Смотрят с телефона, в среднем 40 секунд. Главная задача сайта — за первый экран показать уровень владения фронтендом (сайт сам является демо), за следующие 30 секунд — дать список проектов со стеком и ссылками на код, в конце — способ связаться.

Из этого следуют два жёстких приоритета:

1. **Сайт — это витрина навыка.** Небрежная анимация, дёрганый скролл или 4 секунды до первого кадра вредят сильнее, чем отсутствие 3D вообще.
2. **Контент важнее эффекта.** 3D-фон не должен мешать читать текст, попадать в кнопки и работать с клавиатуры.

### Модель контента

Ядро сайта — **витрина проектов**: грид карточек на главной, клик по карточке открывает внутреннюю страницу проекта с галереей и разбором. Ссылка на репозиторий — один из элементов этой страницы, а не замена ей.

Это **не** автоматический агрегатор гитхаба. Список проектов курируется вручную в `data/projects.ts`: туда попадает только то, что готово показывать. Живые данные GitHub API (последний коммит, звёзды, основной язык) подмешиваются поверх курируемой записи по полю `links.repo` — обогащают карточку, но не формируют список.

Почему так: автоподтяжка всех репозиториев вытаскивает форки, учебные задания и недоделки без README, и отнимает контроль над обложкой и описанием — то есть ровно над тем, что продаёт проект.

Грид, не слайдер. Слайдер прячет часть работ за жестом, хуже работает на мобильном и с клавиатуры и мешает индексации.

## 4. Структура

```
src/
  app/                    # роутер, провайдеры, глобальные стили
    routes.tsx
    styles/global.css     # @theme токены Tailwind v4
  pages/
    Home.tsx              # сборка секций главной
    ProjectPage.tsx       # /work/:slug — страница кейса
    NotFound.tsx
  sections/               # секции главной страницы, по одной на файл
    Hero/
    Work/                 # грид карточек проектов
    Stack/
    Contact/
  components/             # переиспользуемое UI: Button, Tag, Link, Section
  scene/                  # ВСЁ, что импортирует three
    Backdrop.tsx          # <Canvas>, точка входа, грузится через lazy()
    layers/               # слои параллакса
    hooks/                # usePointerParallax, useReducedMotion, useInViewport
  data/
    projects.ts           # массив проектов
    stack.ts              # справочник технологий
  lib/                    # чистые утилиты, без React
  types/
```

Правила:

- **`three` импортируется только внутри `src/scene/`.** Секции знают о сцене через один ленивый компонент `<Backdrop />`. Если `three` попадёт в основной чанк — считать это багом.
- Секция = папка с `index.tsx` и локальными подкомпонентами. Локальный компонент не выносим в `components/`, пока он не понадобился второй раз.
- Данные — статические типизированные модули, без CMS и без fetch на клиенте.

## 5. Дизайн

Направление: **инженерная телеметрия**, а не неоновый киберпанк. Ощущение приборной панели: холодный металл, точные тонкие линии, один сигнальный цвет, много воздуха. Никаких глитч-эффектов, сканлайнов, «Матрицы» и фиолетово-голубых градиентных заливок.

### Палитра

Определяется в `global.css` через `@theme`, в коде используются только токены — хардкод hex в JSX запрещён.

```css
@theme {
  --color-void:   #05080d;  /* фон страницы */
  --color-hull:   #0d141d;  /* поверхности, карточки */
  --color-steel:  #24303e;  /* границы, разделители */
  --color-haze:   #7d8fa3;  /* второстепенный текст */
  --color-ice:    #e8eef4;  /* основной текст */
  --color-signal: #ff8a3d;  /* единственный акцент */
}
```

Про акцент: `--color-signal` означает «здесь что-то живое или интерактивное» — активная ссылка, фокус, статус проекта, точка на таймлайне. Он не используется для декора и не появляется больше 2–3 раз на экране. Всё остальное живёт на холодной шкале.

Фон не плоский чёрный: очень медленный радиальный градиент от `--color-hull` в центре к `--color-void` по краям + едва заметное зерно (SVG-шум, ~3% opacity). Это даёт глубину под 3D-слоем.

### Типографика

- Заголовки: **Archivo** (расширенное начертание, вес 600), крупно, плотный трекинг.
- Текст: **IBM Plex Sans**, вес 400, длина строки ≤ 72 символа.
- Моноширинный: **IBM Plex Mono** — только для настоящих машинных данных: версии, хеши коммитов, год, размер бандла. Не для декоративных подписей.

Шрифты подключаются локально (`@fontsource-variable`), с `font-display: swap`, подгружаются только нужные веса.

Шкала: 12 / 14 / 16 / 20 / 28 / 40 / 64 / 96. На мобильном крупные ступени сжимаются через `clamp()`.

Чего не делать: не выделять одно слово в заголовке другим цветом; не ставить над каждым блоком капслочный «eyebrow»-лейбл; не соединять мета-строки точками-разделителями; не добавлять «→» в текст кнопок.

### Сетка и композиция

- Контент выровнен по левому краю, максимальная ширина 1200px, поля 24px на мобильном / 64px на десктопе.
- Ритм между секциями кратен 8. Между секциями — 96–160px.
- Разделители секций — тонкая линия `--color-steel` шириной в колонку, а не на всю ширину экрана. Линия несёт смысл: она показывает границу колонки контента.
- Скругления: 2px на всём, кроме аватара. Крупные радиусы уводят в SaaS-эстетику.
- Теней нет. Глубина создаётся границей и фоном поверхности.

### Движение

- Одна оркестрованная сцена на загрузку главной: сначала проявляется 3D-фон, затем заголовок. Всё остальное появляется без анимации.
- Никаких fade-in-up на каждой секции при скролле и никаких hover-подъёмов у каждой карточки — это главный признак шаблонной страницы.
- Ховер меняет цвет границы и подчёркивание, не трансформирует блок.
- Все переходы 120–200мс, `ease-out`.

## 6. 3D-фон: спецификация и бюджет

### Идея

Три слоя точек на разной глубине, образующие разреженную решётку (не «звёздное поле» и не хаотичные частицы). Слои сдвигаются параллаксом от курсора и от скролла с разными коэффициентами: дальний 0.2, средний 0.5, ближний 1.0. Решётка очень медленно дышит по синусоиде. Никаких резких движений — фон должен восприниматься периферийным зрением и не отвлекать от текста.

Поверх сцены — вертикальный градиент от прозрачного к `--color-void`, чтобы текст всегда лежал на достаточном контрасте.

### Технические требования

Это не рекомендации, это условия приёмки:

- `<Canvas>` рендерится **только** через `React.lazy` + `Suspense`. Fallback — статический градиент, идентичный по цвету, чтобы не было вспышки.
- `dpr={[1, 1.75]}`, `gl={{ antialias: false, powerPreference: 'high-performance' }}`.
- Точки — один `InstancedMesh` или `Points` на слой. Три draw call максимум.
- Внутри `useFrame` — ноль аллокаций: никаких `new Vector3()`, объекты создаются один раз вне колбэка. Анимация опирается на `delta`, не на номер кадра.
- Рендер останавливается, когда вкладка скрыта (`document.hidden`) и когда canvas ушёл из вьюпорта (`IntersectionObserver`).
- Количество точек зависит от устройства: десктоп ~4000, мобильный ~1200. Порог — по ширине вьюпорта, не по user-agent.
- При `prefers-reduced-motion: reduce` сцена рендерит один статичный кадр и останавливается. Параллакс от курсора выключен.
- Ручной lite-режим: переключатель в футере, состояние в Zustand + localStorage. При выключении 3D сцена полностью размонтируется, геометрии и материалы освобождаются в `dispose`.
- Canvas — `aria-hidden="true"`, `pointer-events: none`, не участвует в порядке фокуса.

### Бюджет производительности

| Метрика | Порог |
|---|---|
| LCP (мобильный, 4G) | < 2.5 s |
| Initial JS (gzip, без чанка сцены) | < 120 kB |
| Чанк сцены (gzip) | < 250 kB |
| CLS | < 0.05 |
| FPS на среднем ноутбуке | стабильные 60 |
| Lighthouse Performance (мобильный) | ≥ 90 |

Если эффект не влезает в бюджет — упрощается эффект, а не поднимается порог.

## 7. Доступность

Не опциональный слой, проверяется в каждой итерации:

- Контраст текста ≥ 4.5:1 **поверх реального фона со сценой**, не поверх чистого `--color-void`.
- Видимый фокус на всех интерактивных элементах: рамка `--color-signal`, 2px, со смещением. `outline: none` без замены — запрещено.
- Семантическая разметка: `header`, `main`, `section` с `aria-labelledby`, `footer`. Одна `h1` на страницу.
- Все интерактивные элементы достижимы с клавиатуры, порядок фокуса совпадает с визуальным.
- У изображений осмысленный `alt` (или пустой, если картинка декоративная).
- Ссылки на внешние ресурсы: `rel="noopener noreferrer"`.

## 8. Модель данных

```ts
// src/types/project.ts
export type ProjectStatus = 'live' | 'wip' | 'archived';

export interface Project {
  slug: string;                 // url страницы кейса
  title: string;
  tagline: string;              // одна строка, ≤ 90 символов
  year: number;
  role: string;                 // "фулстек", "фронтенд", "пет-проект"
  status: ProjectStatus;
  stack: TechId[];              // ссылки на справочник, не свободный текст
  highlights: string[];         // 2–4 пункта: что решено, а не что использовано
  links: {
    repo?: string;              // формат "owner/repo", отсюда же тянутся живые данные
    demo?: string;
  };
  cover: Image;                 // обложка в гриде и в OG
  featured?: boolean;           // крупная карточка в гриде
  case?: ProjectCase;           // если есть — карточка ведёт на /work/:slug
}

export interface Image {
  src: string;
  alt: string;
  width: number;                // обязательно, иначе поедет CLS
  height: number;
}

/** Содержимое внутренней страницы проекта */
export interface ProjectCase {
  problem: string;              // что требовалось решить и почему это было нетривиально
  solution: string;             // как решено, какие развилки были
  outcome: string;              // результат: что работает, чем измеряется
  lessons?: string;             // что не получилось или что переделал бы
  gallery: Image[];             // 2–6 изображений: экраны, схема, до/после
}
```

```ts
// src/types/tech.ts
export type TechCategory = 'frontend' | 'backend' | 'infra' | 'tooling';

export interface Tech {
  id: TechId;
  label: string;                // "PostgreSQL", а не "postgres"
  category: TechCategory;
}
```

Правила по контенту проектов:

- `highlights` описывают задачу и результат, а не перечисляют технологии. Плохо: «использован Zustand». Хорошо: «состояние редактора синхронизируется между вкладками».
- Стек проекта задаётся только через `TechId`, чтобы фильтр по технологиям работал без нормализации строк.
- Проект без `repo` и без `demo` — допустим, но тогда нужен кейс, иначе его нечем подтвердить.

## 9. Итерации

Работаем строго по порядку. Не начинать следующую, пока предыдущая не проходит проверки из раздела 12.

**Итерация 1 — каркас и первый экран**
Поднять Vite + TS + Tailwind v4, токены темы, шрифты, лэйаут, роутер. Hero: имя, одна строка о специализации, кнопки «Проекты» и «Связаться». 3D-фон со всеми требованиями раздела 6, включая lite-режим и reduced-motion. Секции-заглушки с корректной семантикой. Деплой должен работать в конце итерации.

**Итерация 2 — грид проектов**
`data/projects.ts`, `data/stack.ts`. Секция Work: грид карточек. Плитки не одинаковые: `featured`-проект занимает два столбца, остальные — один. На карточке: обложка, название, tagline, год, роль, статус, стек, ссылки на репозиторий и демо. Клик по карточке ведёт на `/work/:slug`, если у проекта есть `case`; если нет — открывает репозиторий во внешней вкладке, и это видно по иконке. Фильтр по технологии, состояние фильтра — в URL (`?tech=react`), чтобы ссылкой можно было поделиться. Пустой результат фильтра — не «ничего не найдено», а строка с понятным выходом (сброс фильтра). Секция Stack: технологии по категориям, без процентных шкал владения — они ничего не значат и выглядят наивно.

**Итерация 3 — страницы проектов**
Роут `/work/:slug`, страница кейса: заголовок, мета-строка (год, роль, статус, стек), разбор по блокам `problem / solution / outcome / lessons`, галерея. Кнопки на репозиторий и демо — в шапке страницы и в конце. Навигация «предыдущий / следующий проект». 3D-фон на этих страницах приглушён или отключён — здесь читают, а не любуются. Галерея: клик открывает изображение крупно, закрытие по `Esc` и по клику вне, фокус возвращается на миниатюру, стрелки переключают кадры. Изображения ниже первого экрана — `loading="lazy"`.

**Итерация 4 — контакты и завершение**
Футер: email с копированием в один клик, GitHub, Telegram, LinkedIn. Форма — только если появится обработчик (Formspree/Resend), иначе честная mailto-ссылка лучше нерабочей формы. Плашка доступности для работы. SEO: title, description, canonical, OG-картинка, `JSON-LD` типа `Person` на главной и `CreativeWork` на страницах кейсов, favicon, `robots.txt`, `sitemap.xml` со всеми слагами проектов. Страница 404.

**Итерация 5 — живые данные GitHub (опционально)**
Подтяжка по `links.repo`: дата последнего коммита, звёзды, основной язык. Запрос на сборке или через кэш в `sessionStorage` с TTL — не на каждый рендер. Обязателен фолбэк: при ошибке или лимите API карточка выглядит целой, просто без этих полей. Живые данные никогда не влияют на состав списка проектов.

**Дальше (по решению владельца)**
Командная палитра `Cmd+K`, RU/EN, раздел экспериментов, генерация PDF-резюме из `data/`.

## 10. Соглашения кода

- Именование: компоненты `PascalCase`, хуки `useCamelCase`, константы `SCREAMING_SNAKE`, файлы совпадают с именем экспорта.
- Один экспорт по умолчанию на файл-компонент, именованные экспорты для утилит.
- Пропсы описываются `interface`, юнионы и алиасы — `type`.
- Никакой бизнес-логики в JSX: вычисления выносятся в хуки или `lib/`.
- Классы Tailwind собираются через `clsx`/`cva`, длинные списки классов не склеиваются шаблонными строками с условиями.
- Комментарии объясняют «почему», а не «что». Код, требующий комментария «что», переписывается.
- Магические числа в сцене (скорости, коэффициенты параллакса, плотность точек) выносятся в именованные константы в одном файле `scene/config.ts`.
- Коммиты: Conventional Commits (`feat:`, `fix:`, `perf:`, `chore:`), на русском или английском — но единообразно в рамках проекта.

## 11. Чего не делать

- Не добавлять UI-библиотеки и не тянуть готовые шаблоны портфолио.
- Не ставить `any`, `@ts-ignore`, `eslint-disable` без комментария с причиной.
- Не использовать `localStorage`/`sessionStorage` в компонентах напрямую — только через одну обёртку в `lib/storage.ts`.
- Не анимировать `width`, `height`, `top`, `left` — только `transform` и `opacity`.
- Не грузить обложки проектов в исходном разрешении: WebP, `srcset`, `loading="lazy"` для всего, что ниже первого экрана.
- Не писать на сайте «мотивированный разработчик», «быстро обучаюсь», «страсть к коду» и прочий шум. Тексты — конкретные: что сделано, чем измеряется.
- Не показывать проценты владения технологиями и не рисовать бейджи shields.io.
- Не добавлять анимированный набор текста в hero, кастомный курсор-кружок, прелоадер с процентами и секцию отзывов без реальных отзывов.
- Пустые состояния и ошибки формулируются как действие: что произошло и что сделать дальше. Не «ничего не найдено», не извинения.
- Не разворачивать большие рефакторинги, если задача была локальной. Сначала предложить план.

## 12. Готовность итерации

Итерация считается закрытой, когда одновременно верно:

1. `pnpm typecheck && pnpm lint && pnpm build` проходят без ошибок и предупреждений.
2. Lighthouse на мобильном профиле: Performance ≥ 90, Accessibility = 100.
3. Страница просматривается и управляется только с клавиатуры.
4. При `prefers-reduced-motion: reduce` и в lite-режиме сайт полностью функционален.
5. Проверено на 360px, 768px, 1440px — без горизонтального скролла.
6. При выключенном WebGL страница выглядит целостно, а не сломанно.
